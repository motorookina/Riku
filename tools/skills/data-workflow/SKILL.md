# data-workflow（数据下载/更新工作流规范）

针对**数据下载与更新任务**的总纲：**先查已有什么 → 增量补缺 → 批量一次到位 → 落盘/入库 → 摘要收尾**。与 `tushare-pro`（怎么拉）、`sql-pro`（怎么写库）配合使用。

## 何时使用

当任务涉及「下载 / 更新 / 刷新 / 增量 / 同步」金融数据，无论最终落到文件还是数据库，都先遵守本技能。

## 何时不使用

- 纯投资分析 / 问答，不涉及数据获取与落盘
- 单次小规模查询（如随手查一只股票的最新价）——直接调工具即可，不必走完整工作流

## 工作流铁律

### 1. 先查已有什么，再决定下载什么
- 动手前先查目标表/文件已有的数据范围：最新日期、已覆盖的标的/区间。
- 默认**增量更新**：从上次已存的最大日期 +1 开始拉，绝不整表重拉。
- 判断依据示例：
  - 落库：`SELECT max(trade_date) FROM <表>;`（配合 sql-pro）
  - 落文件：先 `ls data/` 看是否有 `{接口}_{标的}_{开始}_{结束}_{日期}.csv`，读其最后日期
- 目标表/文件**不存在**时才是全量下载。

### 2. 复用已有产物
- `/workspace` 和 `data/` 里已有的文件、列表、脚本**直接复用或增量更新**，不重新下载/生成。
- 一次下载结果落盘后，后续任务从文件读，**不重复向数据源请求**。
- 已有脚本优先用（如 tushare-pro 的 `scripts/`），不要现场重写。

### 3. 批量、一次性
- 下载用批量接口（一次多标的/多日期），写库用批量写入（COPY / executemany）。
- **禁止逐条循环调工具**。能一个脚本跑完的，绝不拆成多次工具调用。
- 大批量任务：写一个脚本在容器里一次跑完，只把「完成情况摘要」带回对话。

### 4. 数据不进对话
- 大表数据直接写库/写文件，工具只返回摘要：「写入 N 行，最新日期 X」。
- 确需查看时才返回 head/tail + 行数，不整表贴进对话。

### 5. 写库幂等、可重跑
- 更新一律按日期 **upsert**（`ON CONFLICT ... DO UPDATE`），重复执行不产生脏数据。
- 这让中断后的续跑（`/resume`）可以安全继续，不会因重跑产生重复行。

### 6. 不重复探测/安装
- DB 连接、表结构、环境依赖一次确认后记住，不反复查询。
- 缺依赖优先用已固化的方案（自定义镜像 / 已有脚本），不反复 `pip install`。

### 7. 明确终点，达到即停
- 完成标准明确：「已更新到 {日期}，写入 {N} 行」。
- 达到即停，不重复校验已存数据。

## 标准流程模板

对一次「下载并入库/落盘」任务，按此顺序：

1. **确认目标**：表/文件、标的、时间范围、频率、字段。
2. **检查现状**（铁律 1）：查已有最大日期与覆盖，算出缺口区间。
3. **选接口与脚本**：查 tushare-pro 的接口/脚本；若缺口为空，直接结束并说明「已是最新」。
4. **批量执行**：脚本一次跑完（分段拉取 → 合并去重 → 写入）。
5. **校验**：关键字段、日期连续性、行数符合预期。
6. **摘要返回**：写入 N 行 / 最新日期 X / 失败的标的与区间。

## 与其它技能的关系

| 技能 | 负责 |
|---|---|
| `tushare-pro` | 怎么拉：接口、参数、分段、导出格式 |
| `sql-pro` | 怎么存：建表、批量写入、upsert、查询已有范围 |
| `data-workflow`（本技能） | 怎么安排：先查→增量→批量→幂等→收尾 |

## 典型反例（不要这么做）

- ❌ 不看已有数据，直接整表重拉 → 浪费积分与时间
- ❌ 逐条 `execute` 循环处理几千行 → token 与耗时爆炸
- ❌ 把几万行数据打印进工具结果 → 上下文爆炸
- ❌ 每次任务都重新 pip install / 重新查表结构
- ❌ 重复下载 `data/` 里已存在的文件
